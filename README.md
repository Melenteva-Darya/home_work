# Управление каталогом товаров (Skypro OOP Project)

Инструмент для автоматизации учета категорий и продуктов складского каталога на базе объектно-ориентированного
программирования (ООП) в Python.

---

## 🚀 Описание функционала проекта

В проекте реализована гибкая объектная модель данных для управления структурой товаров:

### 📦 Иерархия классов товаров (Наследование):

* **`Product` (Продукт)**: Базовый класс для хранения информации о товаре. Атрибуты: название (`name`), описание (`description`), цена (`price`) и доступное количество на складе (`quantity`).
* **`Smartphone` (Смартфон)**: Класс-наследник `Product`. Дополнительно содержит: производительность (`efficiency`), модель (`model`), объем встроенной памяти (`memory`) и цвет (`color`).
* **`LawnGrass` (Трава газонная)**: Класс-наследник `Product`. Дополнительно содержит: страну-производитель (`country`), срок прорастания (`germination_period`) и цвет (`color`).

### 🗂️ Класс Категорий:

* **`Category` (Категория)**: Группирует товары и содержит их список (`products`), а также название и описание самой категории. Метод `add_product` защищен с помощью функций `isinstance()` и `issubclass()` — в категорию можно добавить только сам `Product` или его наследников. Попытка добавить объекты других типов вызывает ошибку `TypeError`.

### 🛡️ Строгая валидация сложения (`__add__`):

* Реализована возможность складывать стоимость партий товаров `(цена × количество)`. Сложение разрешено **строго внутри одного и того же класса** (например, Смартфон + Смартфон). Попытка сложить объекты разных классов (например, Смартфон + Трава газонная) вызывает ошибку `TypeError`.

### 📊 Автоматический подсчет метрик (Счетчики классов):

* Ведется сквозной учет общего количества созданных уникальных видов продуктов (`Product.number_of_product`), включая все классы-наследники.
* Ведется автоматический подсчет общего числа созданных категорий (`Category.category_count`).
* Реализован динамический расчет суммарного количества всех добавленных в категории товаров (`Category.product_count`).

## 🧪 Тестирование и качество кода

Проект полностью покрыт автоматическими тестами и настроен в соответствии с современными стандартами разработки:

1. **Тестирование (`pytest`)**: Написаны изолированные тесты с использованием фикстур для проверки инициализации объектов, корректности работы счетчиков классов, а также новой логики наследования, валидации типов и обработки исключений `TypeError`. При каждом запуске автоматически сбрасываются глобальные счетчики.
2. **Покрытие кода (`pytest-cov`)**: Обеспечено **100% покрытие тестами** основной бизнес-логики в модуле `src/product_classes.py`.

    * **`Black`** — для автоматического форматирования кода (лимит строки 119 символов).
    * **`Flake8`** — для статического анализа и проверки стандартов стиля.
    * **`isort`** — для автоматического упорядочивания импортов.
    * **`Mypy`** — для строгой проверки статической типизации на основе аннотаций.

## 🛠 Инструкция по запуску (Шпаргалка)

Все инструменты настроены через конфигурационные файлы `pyproject.toml` и `.flake8` в корне проекта, поэтому команды запуска стали максимально короткими.

### 1. Установка всех необходимых зависимостей

Если у вас ещё не установлены инструменты тестирования и линтинга, выполните:

```bash
pip install pytest pytest-html pytest-cov black isort mypy flake8
```

### 2. Запуск тестов и сбор покрытия

Команда автоматически запускает тесты, выводит таблицу покрытия в консоль и генерирует два HTML-отчета в папку `tests_output`:

```bash
pytest
```

* **Результаты тестов:** смотреть в `tests_output/report.html`
* **Интерактивная таблица покрытия:** смотреть в `tests_output/coverage_report/index.html`

### 3. Автоматическое форматирование кода

Приводит файлы к единому красивому стилю:

```bash
isort . && black .
```

### 4. Проверка качества кода и типов данных

Запуск статического анализа без ругани на длинные строки и служебные папки виртуального окружения:

```bash
mypy src && flake8 .
```

## 🚀 Новые возможности и архитектурные изменения

В проект была внедрена строгая иерархия классов на основе объектно-ориентированного программирования (ООП), механизмы абстракции, логирования и кастомной итерации.

### 1. Абстрактные базовые классы (ABC)
Для исключения дублирования кода и стандартизации интерфейсов добавлены абстрактные классы (модуль `abc`):
*   **`BaseStorage`**: Абстрактный класс для сущностей, предназначенных для хранения и учета. Содержит общие поля `name` и `description`. Является родителем для классов `Category` (Категория) и `Order` (Заказ).
*   **`BaseProduct`**: Абстрактный класс для продуктовой линейки. Декларирует обязательный фабричный метод класса `@classmethod @abstractmethod def new_product()`.

### 2. Новый функционал: Класс «Заказ» (`Order`)
Создан класс `Order` для оформления покупки. Он интегрирован в общую систему и наследуется от `BaseStorage`:
*   **Ограничение по ТЗ**: В заказе может быть указан только **один** товар. Реализована строгая валидация типа данных через `isinstance(product, Product)`. При попытке передать некорректный объект генерируется исключение `TypeError`.
*   **Автоматический расчет**: Итоговая стоимость заказа (`total_cost`) рассчитывается автоматически в момент инициализации на основе переданного количества и цены товара.

### 3. Множественное наследование и логирование (`PrintMixin`)
Класс `Product` переведен на множественное наследование для внедрения сквозной функциональности:
*   **`PrintMixin`**: Кастомный миксин, который автоматически логирует в консоль информацию о создании любого продукта. Вызов конструкторов оптимизирован с учетом цепочки MRO (Method Resolution Order) для предотвращения скрытых ошибок инициализации.

### 4. Паттерн «Итератор» (`ProductIterator`)
Реализована возможность удобного перебора товаров в категории «под капотом»:
*   Создан отдельный класс `ProductIterator`, который принимает объект категории и позволяет перебирать её товары с помощью стандартного цикла `for ... in ...`.
*   В класс `Category` добавлен безопасный инкапсулированный геттер `products_list` для передачи списка объектов итератору, не нарушая приватность данных.
